# 변경 이력

평가 도중 발견한 문제와 수정을 순서대로 기록한다. 결과를 보고 지표를 고른 것이 아님을 보이기 위한 기록이다.

| 단계 | 변경 | 이유 |
|---|---|---|
| Gemma-4 → Gemma-3 | 계획의 Gemma-4 E2B·E4B(Apache-2.0)를 Gemma-3 1B·4B(Gemma Terms)로 교체. **일괄 실행 전** | Gemma-4 공식 GGUF에 `<\|turn>` `<\|channel>` 등 특수 토큰이 제대로 등록되지 않아 모델이 대화 경계를 인식하지 못하고 입력을 이어 씀. 채팅 템플릿 3회 시도 실패. llama.cpp에서 검증된 Gemma-3으로 대체 |
| 9종 → 10종 | Qwen3-14B 추가 | 크기 사다리의 품질 상한 확인. 메모리 관문에서 탈락하는 것을 전제로 참고 열로 둠 |
| 판정 v1→v3 | 정답/부분/오답 → 정답/환각/무응답 3분류 + 유형 | "부분 정답"이 사용자에게 무엇을 주는지 불명확 |
| 정답률 → 정답 안정도 | 점수에서 정답률 대신 평균−표준편차 | 정답률과 이중 계산 방지, 지시문 민감도 반영 |
| 최솟값 → 평균−표준편차 | 안정도 산식 변경 | 지시문 수를 늘릴수록 최솟값이 내려가는 문제 |
| 인용 정확도 계산 수정 | 인용문 속 숫자·문서 조항 번호를 인용으로 세던 오탐 제거, 번호 없는 답변 0 | 규칙 오탐으로 형식이 흐트러진 모델이 과소평가됨 |
| 수치 재현 계산 수정 | 날짜를 한 덩어리로 | 연·월 조각이 우연히 일치해 점수를 받음 |
| **판정 전문 재확인** | 잘렸던 답변 2,210건을 전문으로 재판정, 300건(13.6%) 변경 | 초기 판정 화면이 답변 앞 78~150자만 표시해 끝에 붙는 근거 밖 조언을 놓침 |
| 형식 안정도 관문 제거 | 관문·점수에서 제외, 규칙 기반 참고로 | 평가용 두 줄 형식은 운영 요구가 아님(운영: 판단/근거/유보사항) |
| 라이선스 관문 제거 | 후보 선정 조건으로 이동 | 후보 전원이 이미 충족 |
| 메모리 실측 | 계산 추정 → 운영 설정 실측 | 추정이 모델 크기에 비례해 과소(14B: 10.2 → 14.81GB) |
| 속도 통일 | 노트북 실측+환산 → 워크스테이션 실측 10종 | 같은 장비·같은 조건 비교 |
| 가중합 → 지표별 비교 | 결론 근거를 지표별 순위로, 가중 점수는 참고 | 평가 지표 관리 규정 준수 |
| 58 → 100문항 | 42문항 추가(회사별 20으로 균형) | 기존 표본이 C04·C05에 치우침 |
| 100 → 295문항 | 나머지 195문항 전문 판정 추가 | 표본 판정을 전수 판정으로 확장. 1위·품질 3지표 1위 불변, 민감도 44.1→56.4% |
